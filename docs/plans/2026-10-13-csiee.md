# CSIEE Implementation Plan

**Goal:** Ship a funny, reproducible, option-only multiple-choice baseline repository.

**Architecture:** A dependency-free Python package separates tiny guessing strategies from strict data adapters and evaluation. Strategies see only the options, never the answer or conversation history. Reports record dataset hashes, seeds, chance accuracy, and permutation controls.

**Tech Stack:** Python 3.9+, argparse, unittest, GitHub Actions, JSON/CSV/Markdown.

## Design decisions

The original brief requests Lite (C), Pro (length folklore), Pro Max (combined folklore, including third-largest numeric choice), and real benchmark experiments such as PersonaMem-v2. A notebook-only prototype would be quick but harder to reproduce; a web demo would be shareable but distract from the three-line joke. Build a small installable CLI with shareable reports first.

Pro: a single conspicuously long or short option wins, otherwise C. Pro Max: deterministic voting among longest, shortest when appropriate, numeric third-largest, and less absolute wording; ties prefer C then index. Individual ablations expose each signal. No trained weights or test-set tuning.

## Implementation and verification

1. Create package metadata, option validation, strategies, and unit tests. Verify 2/4/5-choice cases, length rules, numeric ties, and deterministic behavior.
2. Add strict JSONL and PersonaMem-v2 CSV adapters. Shuffle answer-first source data with a stable seeded hash; retain source metadata, never pass labels to strategies. Test malformed labels and duplicate options.
3. Add evaluation CLI, Wilson intervals, expected random baseline, paired original/shuffled reports, per-question predictions, hashes, and JSON/Markdown output. Test mapping correctness and reproducibility.
4. Add an opt-in pinned official PersonaMem-v2 downloader, a deliberately synthetic demo, documentation, license, and CI. Keep upstream raw data out of Git.
5. Run real benchmark if the official source is accessible, publish exact provenance and limitations, and verify installed CLI in a clean environment.
6. Initialize Git, create the user's selected GitHub repository, push the tested code, and verify the remote.

Implementation extension: evaluate the unchanged rules on OpenBookQA's official 500-question test split as an additional comparison. Pin the official archive hash and preserve source choice labels; do not redistribute raw data.

## Acceptance

The core strategies remain a few lines each; local demo works without API keys or runtime dependencies; real results are never replaced with synthetic claims; changing option order preserves labels; report reproduction is documented; GitHub publication uses the account selected by the user.
